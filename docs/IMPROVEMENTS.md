## 📌 결정이 필요한 설계 구멍 (codex 지적 + 판단)

| # | 사안 | 결정 | 근거 |
|---|---|---|---|
| D1 | `u`를 "데이터 없음"으로만 쓸지, "규칙상 판정 불가"를 따로 둘지 | **`u` 하나로 두되 사유를 반드시 병기**한다. 등급을 늘리면 사용자가 외워야 할 것이 늘어난다 | 사용자에게 필요한 건 등급 개수가 아니라 "왜 없는가"다 |
| D2 | 법인번호와 상호·지역이 충돌할 때 | **법인번호 > 상호 > 지역.** 번호가 있는데 불일치면 즉시 실패, 지역은 동명이인을 좁힐 때만 보조로 | 번호는 겹치지 않고 상호는 얼마든지 겹친다 |
| D3 | 연결·별도 혼합 | **별도 우선, 시계열은 같은 기준끼리만.** 기준이 섞이면 추세 판정을 하지 않고 최신 1개년만 표시 | 연결·별도를 비교하면 매출 성장이 회계 기준 변경으로 만들어진다 |
| D4 | 공시 캐시 갱신 주기 | **회계연도 기준 재검증.** 캐시된 최신 회계연도가 "지금 나와 있어야 할 연도"보다 낡으면 다시 조회. 한국 12월 결산은 4월에 감사보고서가 나오므로 5월 이후 기준 | 날짜 TTL은 공시 주기와 무관해 헛조회 또는 낡은 값을 만든다 |
| D5 | "전수조사"의 완료 조건 | **부분 성공을 부분 성공이라고 표시한다.** 키워드별·보드별 성공/실패/잘림을 manifest에 남기고 리포트 상단에 경고 | 조용한 부분 실패가 이 제품에서 가장 나쁜 실패다 |
| D6 | 사라진 공고·마감·재공고의 상태 모델 | `active` / `closed`(마감 확인) / `stale`(현재 검색 조건 밖) 3상태. **삭제하지 않는다** | 재공고는 새 ID로 올라온다. 지우면 이력이 끊긴다 |
| D7 | 지역 필터 vs 통근 필터 | **통근이 최종 기준, 지역은 사전 컷.** 통근 API 실패는 `drop`이 아니라 `hold` | 추측으로 공고를 버리지 않는다 |
| D8 | 개인용 vs 공유용 리포트 | **기본이 공유 안전.** 지원 상태는 `--with-status`로만 포함 | 실수로 새는 쪽이 실수로 빠지는 쪽보다 훨씬 비싸다 |
| D9 | 재공고를 "같은 자리"로 이을 기준 | **제목 유사도 ≥0.8이 정확히 1건일 때만.** 여럿이면 "이 회사에 살아있는 공고 N건"으로 격하 | 잘못 이으면 남의 자리에 지원 이력이 승계된다. 부분일치 5건 사고와 같은 원칙 |
| D10 | 재검색에서 회사를 특정하는 키 | **원티드 회사 ID(`boardId`) 완전일치.** 없을 때만 정규화 상호 완전일치 | 회사명 `includes`는 "미소 → 미소무역" 함정을 그대로 재현한다 |
| D11 | 되찾은 공고의 범위 | **같은 자리로 연결된 것 + 내 직군 키워드에 걸리는 것만.** 나머지는 건수·제목만 알린다 | 회사의 모든 공고를 끌어오면 되찾기가 잡음 주입이 된다 |
| D12 | 지원 이력 승계 | **자동 승계하되 원 공고 키를 `history`에 보존** | 끊기면 같은 회사에 두 번 지원한다 |
