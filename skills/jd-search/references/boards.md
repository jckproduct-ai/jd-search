# 소스 레지스트리

보드마다 **수집 방식과 마감 판정 신호가 다르다.** 하나의 규칙으로 묶으려 하지 말 것.

> 🔴 `browser` 보드는 실행할 때마다 사용자에게 물어보고 동의를 받은 뒤에만 연다.
> 🔴 요청 간 최소 1초. 백그라운드 자동 순회 금지. `robots.txt` 존중.

## 채용 보드

| 보드 | 수집 | 마감 판정 신호 |
|---|---|---|
| **원티드** | `api` | 공개 API `/api/v4/jobs/{id}` 의 `status` (`active` / `close`). 토큰 0, 가장 빠르다 |
| **사람인** | `api`(공개 웹) | 상세의 `<div class="status">` 블록. 🔴 마감일 경과가 아니다 |
| **잡코리아** | `browser` | `og:description` 의 `마감일:` 필드 |
| **잡플래닛** | `browser` | ⚠️ curl은 403. 브라우저 필요 |
| **리멤버** | `browser` | 임베드 JSON 의 `status` / `closedAt` |
| **인크루트** | `browser` | 목록 페이지 마감 표기 |
| **비즈니스피플** | `browser` | `og:description` 의 `마감일:` 필드 |
| **자사 채용페이지** | `browser` | 임베드 JSON 의 `status` / `closedAt` |
| **LinkedIn** | `off` | 🔴 기본 비활성. 스크래핑 제재가 **사용자 개인 계정**에 온다 |

### 원티드 엔드포인트 (2026-08-10 실측 확정)

```
목록  GET /api/v4/jobs?country=kr&query={키워드}&job_sort=job.latest_order
                       &years=-1&locations=all&limit=100&offset=0
      → .data[] · .links.next 로 이어진다. 다 훑으면 next 가 끊긴다
상세  GET /api/v4/jobs/{id}   → .job.status · .job.detail(본문) · .job.address
      → 404 = 내려간 공고
```

🔴 **통합검색 `/api/chaos/search/v1/results` 는 목록 수집에 쓰지 말 것.** `limit`·`offset`을 무시하고
**12건에서 끊긴다.** 미리보기용이다. 실측에서 "서비스기획" 27건 중 12건만 잡혔다.
회사 단위 재공고 검색에는 위 목록 API에 `query={회사명}`을 넣으면 된다.

### 🔴 원티드는 좌표를 직접 준다 — 지오코딩 키가 필요 없다

`job.address.geo_location.location.{lat,lng}` 와 `job.address.district`(구 단위)가 그대로 들어 있다.
실측 74건 전부 채워져 있었다. 통근 판단에 카카오 로컬 API를 쓸 필요가 여기서는 없다.
(등기주소만 있는 재무 쪽 회사 좌표는 여전히 지오코딩이 필요하다.)

마감으로 판정된 건은 **반드시 회사 단위 재검색**을 한 번 더 한다. ID 하나만 보면 살아있는 자리를 놓친다.

### 사람인 엔드포인트 (2026-08-10 실측 확정 · 키 불필요)

```
목록  GET /zf_user/search/recruit?searchword={키워드}&recruitPage={n}&recruitPageCount=100
                                  &searchType=search&recruitSort=relation[&loc_mcd=101000]
      → <div class="item_recruit" value="{rec_idx}"> 블록. 페이지당 최대 100건, 깊은 페이지도 동작
상세  GET /zf_user/jobs/relay/view-ajax?rec_idx={id}       (74KB) 상태·마감일시·다중 근무지·핵심정보
본문  GET /zf_user/jobs/relay/view-detail?rec_idx={id}&rec_seq=0   (35KB) 상세요강
      → 404 = 삭제된 공고
```

🔴 **`/zf_user/jobs/relay/view` (382KB) 는 쓰지 말 것.** 같은 정보를 5배 무겁게 준다.
🔴 **오픈API `oapi.saramin.co.kr/job-search` 는 access-key 를 요구한다** → 쓰지 않는다.
   "필수 키 1개" 약속을 깨는 것이 얻는 것보다 비싸다 (commute 를 착수하지 않기로 한 것과 같은 기준).

**robots.txt (2026-08-10 확인)**: 위 세 경로는 어느 `Disallow` 에도 걸리지 않는다.
다만 사람인은 `GPTBot`·`Bytespider` 를 전면 차단한다 — **자동 수집을 반기지 않는다는 뜻이다.**
→ 사용자가 직접 열어볼 수 있는 페이지만, 요청 간 1초로, 본인 구직 목적에만 쓴다. 병렬 순회·상주 금지.

#### 🔴 사람인 검색은 "전부 훑기"가 성립하지 않는다

형태소를 쪼개 확장해 **"서비스기획" 한 단어에 10,685건**이 나온다. 따옴표 정확검색도 무효였다(동일 건수).

| 페이지 | p1 | p2 | p3 | p4 | p5 | p6 | p7 | p8 |
|---|---|---|---|---|---|---|---|---|
| 제목 매치율 | 95% | 95% | 88% | **31%** | 2% | 0% | 4% | 13% |

→ 페이지 상한이 아니라 **매치율 바닥**에서 멈춘다. 멈춘 지점과 이유를 manifest 에 남겨 리포트에 싣는다.
서버측 축소는 `loc_mcd`(시·도)·`loc_cd`(구)·`cat_kewd`(직무 카테고리)가 동작한다.

#### 🔴 마감 판정은 상태 블록 하나로만 한다

| `<div class="status">` | 판정 | `dueKind` |
|---|---|---|
| `<div class="info_timer">` | 진행중 | `date` (마감일 있음) |
| `<p class="copy once">상시 채용` | 진행중 | `always` |
| `<p class="copy once">채용시 마감` | 진행중 | `untilFilled` |
| `<p class="copy end">마감되었습니다` | 마감 | — |

**날짜 경과를 근거로 쓰면 안 된다.** 실측 목록 40건 중 **9건(22%)이 마감일 자체가 없는** 상시·채용시 공고다.
지원 버튼(`sri_btn_immediately` / `sri_btn_expired_apply`)으로 교차 확인하고, **어긋나면 `unknown`** 으로 둔다.

#### 🔴 목록만 믿으면 안 되는 것 세 가지

1. **마감 표기에 연도가 없다** (`~ 09/20`). 연도를 추정하면 12월→1월에서 통째로 틀린다 → 상세 값만 쓴다
2. **근무지를 첫 곳만 보여 준다.** 실제로는 여러 곳일 수 있다 → 상세의 `근무지역` 전부를 `location.all` 에 담고,
   게이트는 **하나라도 들면 통과**시킨다. 시·도가 생략된 항목("서초구")은 **앞 항목의 시·도를 물려받는다**
3. **좌표가 없다** (원티드와 다르다) → 직선거리를 표시하지 않는다. 지어내지 않는다

#### 🔴 본문이 이미지뿐인 공고가 흔하다 (실측 14건 중 3건)

글자가 없는데 JD 원문 파일을 만들면 **"내용이 있는 것처럼 보이는 빈 기록"** 이 되고, 수집기가 그걸
원문 확보로 세어 다시 받지 않는다. 공고가 내려가면 그대로 영구 손실이다.

→ `본문 형태: 이미지만` 이라고 적고 **이미지 주소를 남긴다.**
→ 조회 실패(`failed`)와 이미지형(`imageOnly`)을 구분한다. 실패는 다시 받고, 이미지형은 다시 받아도 이미지다.

### 교차 보드 중복 병합

`board + id` 유니크는 보드 **안**의 중복만 잡는다. 같은 공고가 원티드·사람인에 동시 게재되는 건 흔하다.

```
병합 조건 (전부 충족)
  ① 서로 다른 보드
  ② 정규화 회사명 완전일치        🔴 부분일치 금지
  ③ 제목 유사도 ≥ 0.8            (보드별 수식어를 뗀 뒤에도 비교)
  ④ 시·도까지 붙은 지역 키가 하나 이상 겹칠 것
→ 하나로 합치고 출처 링크를 복수 보관한다 (리포트에 링크 여러 개 표시)
```

🔴 **불확실하면 합치지 않는다.** 안 합치면 중복이 눈에 보이지만, 잘못 합치면 서로 다른 자리 하나가
목록에서 조용히 사라진다. 지역을 모르거나 비슷한 후보가 여럿이면 "중복일 수 있음"으로 표시만 한다.

🔴 **제목 비교 전에 조건 표기를 뗀다.** 실측에서 같은 자리가 이렇게 갈렸다:

```
사람인  "서비스기획 팀원 (부산)"
원티드  "서비스기획 팀원 (신입~5년 이하 / 부산)"     → 원문 유사도 0.64 (보류)
                                                     → 조건 표기 제거 후 1.0 (병합)
```

괄호 안이 **경력·지역·고용형태뿐일 때만** 뗀다. `"프로덕트 매니저 (커머스)"`와 `"(물류)"`는 다른 자리다.
제목 앞 대괄호는 **그 안이 회사명이거나 조건 표기일 때만** 뗀다.

## 기업 재무

### 공공데이터포털 (인증키 1개 필요 · 무료)

계정당 인증키 **1개**를 모든 서비스가 공유한다. 서비스별 키는 없다.
`401` = 키가 틀림 / `403` = 키는 맞고 **그 서비스 권한 반영 대기**(승인 직후 10분~1시간). 이걸 구분해 안내해야 한다.

| 용도 | 엔드포인트 | 파라미터 | 한도 |
|---|---|---|---|
| 기업개요 | `apis.data.go.kr/1160100/service/GetCorpBasicInfoService_V2/getCorpOutline_V2` | `serviceKey` `resultType` `pageNo` `numOfRows` (+`corpNm`\|`crno`) | 10,000/일 |
| 기업재무 | `.../GetFinaStatInfoService_V2/getSummFinaStat_V2` | `serviceKey` `crno` `bizYear` | 10,000/일 |

응답 필드: `enpSaleAmt`(매출) `enpBzopPft`(영업이익) `enpCrtmNpf`(순이익) `enpTastAmt`(총자산) `enpTdbtAmt`(총부채) `enpTcptAmt`(자본총계) `enpEmpeCnt`(종업원수) `enpPn1AvgSlryAmt`(1인평균급여) `enpBsadr`(등기주소) `fnclDcd`(120=별도 / 110=연결)

**연결/별도** — `120`(별도) 우선, 없으면 `110`(연결). 기준선이 별도면 별도끼리 비교해야 한다.
**이용허락범위 제한 없음** — 재배포 제약이 없다. 이 성질이 오픈소스화의 전제다.

### DART 공시 — 🔴 API 키 불필요

웹 공시검색이 공개돼 있어 필요한 게 전부 HTML에 있다. `corpCode.xml`(키 필요) 다운로드도 필요 없다.

| 용도 | 요청 |
|---|---|
| 보고서 목록 + **corp_code** | `POST https://dart.fss.or.kr/dsab007/detailSearch.ax`<br>`textCrpNm` `currentPage` `maxResults` `startDate` `endDate` |
| **법인등록번호**·사업자번호·업종·설립일·주소 | `GET https://dart.fss.or.kr/dsae001/selectPopup.ax?selectKey={corp_code}` |
| 문서 목차 | `GET https://dart.fss.or.kr/dsaf001/main.do?rcpNo={rcpNo}` |
| 재무제표 본문 | `GET https://dart.fss.or.kr/report/viewer.do?rcpNo=&dcmNo=&eleId=&offset=&length=&dtd=` |

`Referer: https://dart.fss.or.kr/dsab007/main.do` 와 일반 User-Agent를 붙여야 한다.

**공시 형태에 따라 갈린다** (재무 누락 35곳 실측, 2026-08-10):

| 형태 | 비율 | 처리 |
|---|---|---|
| 정기보고서 (사업·반기·분기) | 5.7% | 상장사 중심. 정형 데이터 |
| **감사보고서만** | **57.1%** | 비상장 외감. **원문 표 파싱** — 여기가 본진이다 |
| DART 미등록 | 37.1% | `u` 미확인 |

→ **DART 정형 API만 붙이면 커버리지가 2%p밖에 안 오른다.** 감사보고서 파싱이 실제 이득이다.

**감사보고서 파싱은 `scripts/lib/dart_table.mjs`를 쓸 것.** 직접 새로 짜면 아래 셋을 다시 밟는다.

1. 뷰어 목차는 `cnt['dcmNo'] = "…"` 순차 할당 — `viewDoc('a','b',…)` 6인자로 가정하면 전 건 실패한다
2. 텍스트 평탄화 + 정규식은 **주석 컬럼("23,28")을 값으로** 집는다 → `<tr>/<td>` 구조로 읽고 "주석" 헤더 컬럼을 배제
3. 적자면 계정명이 **"영업손실"이 되고 값은 양수**로 적힌다 → **부호가 라벨에 실린다**
4. 회계연도를 문서 내 날짜 최댓값으로 잡으면 리스 만기(2027년)가 걸린다 → 제출연도를 상한으로

**금융업**(은행·증권)은 계정 양식이 다르다. `매출액` 대신 `영업수익`을 본다.

### 국민연금 사업장 (재무가 없을 때)

가입자 수(≈인원)·월평균 보수(≈급여). 재무는 아니지만 규모 추정은 된다.
재무가 없고 이것만 있으면 등급은 `u`로 두되 **면접 질문은 이 근거로 만든다.** 근거가 아예 없으면 질문도 만들지 않는다.

## 통근 (선택)

| 용도 | 서비스 | 한도 | 발급 |
|---|---|---|---|
| 주소 → 좌표 | 카카오 로컬 | 300,000/일 | developers.kakao.com → REST API 키 |
| 대중교통 경로 | ODsay LAB | 1,000/일 | lab.odsay.com |

🔴 **ODsay `path[0]`은 최단경로가 아니다.** `OPT=0`의 첫 경로는 "추천"이다. 실측에서 첫 경로 63분 vs 실제 최소 44분(19분 오차)이 났고 98곳 전부가 이 오차를 먹었다.
→ **반환된 전 경로 중 `info.totalTime` 최소를 고른다.**

🔴 **등기주소 ≠ 실제 근무지.** 공고 강남 / 등기 부산 같은 사례가 흔하다.
→ 시·도가 어긋나면 등기주소를 버리고 공고 지역 중심점을 쓴다. **어느 기준으로 계산했는지 반드시 표기한다.**

🔴 **카카오 장소검색은 주소만 대조하면 안 된다.** 회사명으로 검색하면 결제 가맹점이 먼저 잡힌다(실측에서 다이소 지점이 통과해 통근 시간이 배로 잘못 나왔다).
→ `place_name`이 질의어를 포함하는지까지 검사한다.

등기주소는 `"역삼동 테헤란로5길 7 (…) 9층"`처럼 지번·도로명·층이 섞여 와서 한 번에 지오코딩되지 않는다.
→ `원문 → 괄호 제거 → 층/호 제거 → 지번 동 제거 → 도로명 번호까지 → 상호 키워드 검색` 순으로 깎으며 재시도한다.
