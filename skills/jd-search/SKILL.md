# jd-search

**이력서 1개 + 집주소 1개를 넣으면, 다닐 수 있는 범위 안의 내 직군 공고를 전부 모아 회사 재무 위험도까지 붙여 리포트 한 장으로 만든다.**

수집만 하는 도구는 이미 많다. 이 스킬의 값어치는 **공고에 회사의 재무 사실을 붙이는 것**과 **범위 밖을 애초에 안 보여주는 것**에 있다.

> **지금 실제로 되는 것 (2026-08-18)**: 원티드·사람인·점핏·인크루트 수집 · 저장본에서 공고 주소 뽑기 ·
> 교차 보드 중복 병합 · 지역 필터 ·
> 마감 재확인 및 재공고 되찾기 · 재무 판정 · 동명이인 확인 · 리포트 · `serve`(상태 변경·추가·숨김).
> **아직 안 되는 것**: 통근 시간 실측(`commute`) · 잡코리아·잡플래닛·로켓펀치의 **목록 자동 수집**
> (셋 다 목록이 JS 로 그려지거나 막혀 있다 — 저장본으로 넣는다) · 링크드인(열지 않는다).
> 🔴 안 되는 것을 되는 것처럼 말하지 않는다. 리포트에도 같은 문구가 실린다.

> 궁합 점수(S/A/B 티어, "87% 일치")는 만들지 않는다. 검증할 수 없는 숫자다.
> 이력서로 하는 일은 둘이다 — **검색 키워드를 만드는 것**, 그리고 JD 와 맞대어
> **겹친 낱말·공백 낱말을 세는 것**. 센 낱말은 눌러서 확인할 수 있는 근거지만,
> 그걸 비율 하나로 뭉치는 순간 검증할 수 없는 숫자가 된다. 그 선을 넘지 않는다.

## 이 스킬을 쓰는 때

- "내 조건에 맞는 공고 찾아줘" / "이직 자리 좀 모아줘"
- "이 회사 재무 어때?" / "지원해도 되는 회사야?"
- "지난주 이후 새로 올라온 공고만 보여줘"
- "○○ 공고 아직 살아있어?"

## 준비물

| 필요한 것 | 필수 | 없으면 |
|---|---|---|
| Node 20+ | ✅ | 동작 안 함 |
| 공공데이터포털 인증키 | 재무 쓸 때 | 재무 없이 수집만 |
| 카카오 · ODsay 키 | 통근 실측 쓸 때 | 지역 필터만으로 동작 |
| LLM 키 | ❌ **불필요** | 이 스킬을 실행하는 에이전트가 그 역할을 한다 |

> DART 공시는 **키 없이** 조회한다. 웹 공시검색이 공개돼 있다. (`scripts/lib/dart.mjs`)

## 첫 실행 — 설치하고 딱 한 번

`~/.jd-search/<프로필ID>/profile.yml` 이 없으면 여기부터 한다. **묻지 않고 넘어가지 말 것.**

🔴 **이 절차를 마치기 전에 수집을 돌리지 않는다.** 조건을 안 정하고 모으면 200건을 받아
걷어내는 데 처음부터 다시 하는 것보다 오래 걸린다. 순서가 뒤집히면 도구가 아니라 짐이 된다.

🔴 **확인 화면 1회 + 위치 1회.** 이 둘이 반드시 거쳐야 하는 전부다.
나머지(제외 키워드·관심 회사·요구경력 하한)는 **비워 둔 채로 끝낼 수 있는 선택 항목**이고,
같은 확인 화면에서 고칠 수 있는 기본값으로 보여 준다. 질문을 따로 세우지 않는다.
🔴 예외는 **연차 하나뿐이다.** 이력서에서 안 나오면 반드시 묻는다 — 넘겨짚으면 목록이 통째로 어긋난다.
질문을 여섯 번 던지면 사람은 세 번째에서 그만둔다.

```
0  이력서를 받는다            필수. 없으면 직군 프리셋으로 대체
1  뽑아서 보여준다            포지션 · 연차 · 겹침 낱말 · 선택 항목 기본값 → 한 화면에 묶어 확인 1회
                             (연차만은 이력서에 없으면 따로 묻는다)
2  묻는다                     출근 가능 지역 — 실제로 공고를 거르는 것은 이것뿐이다
                             자택 주소 · 원격 처리는 같은 자리에서 함께 받는다
3  알려준다                   제출 서류. 포트폴리오는 선택
4  저장한다                   profile.yml 한 파일. 다시 묻지 않는다
```

### 0. 이력서를 먼저 받는다

```
시작하기 전에 이력서를 주십시오. 파일을 주시거나 내용을 붙여 넣으셔도 됩니다.
이력서에서 직무 키워드·연차·도메인을 뽑아 검색 조건을 대신 만듭니다.
경력기술서·포트폴리오가 있으면 함께 주십시오 — 없어도 진행됩니다.
```

```
이력서       → 직무 키워드 · 경력 연차 · 직군        (검색 조건의 뼈대)
경력기술서   → 도메인 · 프로젝트 성격                (키워드 정밀화, 제외어 판단)
포트폴리오   → 산업 · 제품 태그                      (겹침 낱말 보강 + 보관)
```

원본은 `~/.jd-search/<프로필ID>/docs/` 에 두고 `documents` 에 경로만 적는다.

**이력서가 없다고 하면** `references/role-presets.yml` 에서 직군을 고르게 한다.
QA·백엔드·프론트엔드·데이터·디자인·마케팅 등이 들어 있다. 목록에 없는 직군이면 프리셋을
새로 만들어 주고, 저장소에 PR 로 보내도 좋다고 알린다.

🔴 **이력서도 프리셋도 없이 수집으로 넘어가지 않는다.** `target.roles` 가 비면 사람인은
형태소를 쪼개 확장해 한 단어에 1만 건을 내놓는다. 멈출 근거가 없어진다.

### 1. 뽑은 것을 한 화면에 묶어 보여준다 — 확인은 한 번만

```
이력서에서 이렇게 읽었습니다. 고칠 것만 말씀해 주십시오.

  포지션   서비스기획 · 서비스 기획 · 프로덕트 매니저 · 프로덕트 오너
           Product Manager · Product Owner · PM · PO · UX 기획
  제외     사업개발 · 전략기획 · 경영기획
  연차     12년  (공고를 버리는 데 쓰지 않습니다. 목록을 나누는 데만 씁니다)
  겹침 낱말 B2B SaaS · 커머스 · 0→1 출시 · 화면 설계 · 퍼널 분석 · 이해관계자 조율
           (공고 본문과 맞대어 겹친 것/빠진 것을 셀 때 씁니다)
```

🔴 **확인 없이 수집에 넣지 않는다.** 오탐이 그대로 200건 딸려 온다.

🔴 **한국 잡보드에서 실제로 쓰는 표기를 빠짐없이 넣는다.** `PO` 만 넣고 `프로덕트 오너` 를
빼면 한글 표기 공고가 **전량 조용히 사라진다**(실측 확인). 영문 약어는 낱말 경계로 매칭하므로
한글 제목에는 걸리지 않는다.

🔴 **연차를 시니어로 넘겨짚지 않는다.** 문서에서 안 나오면 **반드시 묻는다.**

```
신입 · 인턴만 있음
→ years: 0 으로 잡습니다. `경력무관`·`신입` 공고가 본 목록에 뜨고,
   요구경력이 있는 공고는 `요구경력 높음`으로 따로 표시됩니다.

경력 4년
→ years: 4. 요구경력 낮은 공고까지 걸러 내고 싶으면 하한을 정해 주십시오. 안 정하면 전부 같이 봅니다.
```

🔴 `acceptExperienceFloor`(요구경력 하한)는 **사용자가 원한다고 말할 때만 넣는다.**
기본값으로 넣어 버리면 신입·주니어의 목록 대부분이 "따로 모음"으로 빠져 정작 볼 것이 안 보인다.

**겹침 낱말**은 `node scripts/fit.mjs --terms` 로 뽑는다. 이력서·경력기술서·포트폴리오를
`references/jd-terms.yml` 사전으로 훑어 걸린 낱말만 내놓는다.
🔴 그 출력을 **그대로 profile 에 적지 않는다.** 위 화면처럼 보여주고 확인받은 뒤에 적는다.

### 2. 위치 — 여기서만 묻는다

```
자택 주소        — 동·읍·면까지면 충분. 상세주소 불필요
가고 싶은 지역   — 시·군·구 다중. 🔴 지금 공고를 실제로 거르는 것은 이것뿐이다
원격 처리        — 풀리모트를 거리 무시로 볼지
편도 통근 상한   — ⏳ 물어도 되지만 **아직 적용되지 않는다.** 기록만 된다
```

🔴 **통근 상한을 되는 것처럼 묻지 않는다.** 통근 실측(`commute`)이 미구현이라 값을 받아도 거르지 않는다.
묻는 그 자리에서 이렇게 말한다:

```
편도 통근 상한도 받아 둘까요? 지금은 기록만 되고 공고를 거르지는 않습니다
— 통근 시간 실측이 아직 없어서, 실제로 거르는 건 위에서 고른 지역뿐입니다.
```

🔴 `분당` 같은 줄임말은 시·군·구로 되물어 확정한다. `중구`·`서구`·`남구`처럼 여러 광역시에
같은 이름이 있는 곳은 시·도까지 확인한다 — 부산 중구가 서울 중구를 찾는 사람 목록에 들어온 적이 있다.

🔴 자택 주소는 `~/.jd-search/<프로필ID>/profile.yml`에만 남고 **리포트에는 좌표조차 나가지 않는다.**
프로필 디렉터리는 `0700`, 파일은 `0600`으로 만든다 — 같은 컴퓨터의 다른 계정이 읽지 못하게.

### 3. 제출 서류 — 알려만 준다, 받아내지 않는다

포지션에 따라 낼 것이 다르다. 온보딩에서 정해 두면 공고마다 다시 헤아리지 않아도 된다.

```
이 직군은 대체로 이렇게 요구합니다.

  이력서       필수
  경력기술서   필수      (경력직 공고는 대체로 요구합니다)
  포트폴리오   선택      🔴 안 내도 되는 자리가 많습니다. 지금 없어도 그대로 진행합니다.
                        UX·디자인 계열 공고에서만 필수로 표시해 드립니다.
```

`apply.docs` 에 저장하고, 직군마다 다르면 `apply.byRole` 로 덮어쓴다.

🔴 **이건 준비 체크리스트지 필터가 아니다.** 포트폴리오가 없다고 공고를 버리지 않는다.
🔴 **포트폴리오를 기본 필수로 두지 않는다.** 없는 사람이 지원을 접는다.

### 4. 거르기 · 관심 회사 — 1번 확인 화면의 기본값으로 함께 보여 준다

🔴 **여기서 질문을 새로 세우지 않는다.** 1번에서 보여 준 확인 화면에 기본값으로 얹고,
고칠 것이 있으면 그때 말하게 한다. 비워 둔 채로 끝내도 파이프라인은 돈다.

```
제외 키워드   — 키워드가 겹쳐 딸려 오는 직무 (예: 사업개발, 전략기획)
제외 업종
관심 회사     — 🔴 조건과 무관하게 항상 수집한다. 통근 90분이어도 본다
```

### 5. 저장

`references/profile.example.yml` 구조로 `~/.jd-search/<프로필ID>/profile.yml`에 쓴다.
**여기까지가 전부다. 같은 것을 다시 묻지 않는다.** 조건을 바꾸고 싶으면 그 파일을 고치거나
말로 바꿔 달라고 하면 된다.

## 반복 실행 — 파이프라인

```
1 collect    잡보드 → 원시 공고                    scripts/collect_wanted.mjs
                                                  scripts/collect_saramin.mjs
                                                  scripts/collect_jumpit.mjs
                                                  scripts/collect_incruit.mjs
                                                  scripts/collect_saved.mjs   ← 저장한 HTML
2 merge      보드 간 중복 합치기                    scripts/merge_boards.mjs
3 gate       지역·제외조건으로 컷                   scripts/gate.mjs
4 alive      마감 재확인 + 재공고 되찾기            scripts/check_alive.mjs
5 finance    회사 → 재무 → 자금등급                 scripts/finance.mjs
6 commute    상위 후보만 통근 정밀 실측 (선택)      scripts/commute.mjs       (미구현)
7 fit        이력서 ↔ JD 겹침·공백 (선택)           scripts/fit.mjs
8 render     report.html                           scripts/render.mjs

  수시       공고 하나 손으로 추가                  scripts/add_posting.mjs
  수시       동명이인 확인                          scripts/resolve_company.mjs
  수시       상태 변경·추가·숨김 (로컬 서버)        scripts/serve.mjs
```

```bash
node scripts/collect_wanted.mjs          # 프로필의 target.roles 로 검색. --query 로 덮어쓸 수 있다
node scripts/collect_saramin.mjs         # --pages(목록 깊이) · --max(상세 조회 상한)
node scripts/collect_jumpit.mjs          # 공개 JSON API. 🔴 공백 든 키워드를 무시한다 — 수집기가 알려 준다
node scripts/collect_incruit.mjs         # 공개 검색 페이지. 🔴 EUC-KR
node scripts/collect_saved.mjs --file <저장한.html>   # 목록을 못 받는 보드(잡코리아·잡플래닛·로켓펀치)
                                         # 🔴 첫 실행은 상한 없이 전량이다(20~35분). 시작 전에 예상 시간을 알린다.
                                         #    다음 실행부터 기본 200이고, 상한은 **새로 받아야 하는 건수**만 센다.
node scripts/merge_boards.mjs            # --show 를 주면 아무것도 쓰지 않고 판정만 보여준다
node scripts/gate.mjs
node scripts/check_alive.mjs             # --all 이면 마감 건까지 · --board 로 한 보드만
node scripts/merge_boards.mjs            # 🔴 alive가 공고를 새로 찾았으면 병합부터 다시
node scripts/gate.mjs
node scripts/finance.mjs                 # 키 없이도 돌아간다(DART만). 키는 DATA_GO_KR_KEY 환경변수
node scripts/resolve_company.mjs         # 동명이인이 있으면. 답은 저장돼 다음부터 자동 적용된다
node scripts/fit.mjs                     # 이력서 ↔ JD 겹침·공백. --terms 는 온보딩에서 낱말만 뽑을 때
node scripts/render.mjs                  # 🔴 겹침·공백을 파일에 실으려면 --with-fit 을 명시해야 한다
node scripts/serve.mjs                   # 실제 작업용 화면 (127.0.0.1 전용)
node scripts/test/run.mjs                # 회귀 테스트 — 네트워크 없이 돈다. 손대면 반드시 돌릴 것
```

🔴 **alive는 새 공고를 만든다** — 재공고를 되찾기 때문이다. 그래서 merge·gate·finance를 그 뒤에 다시 돌린다.
전부 멱등이고 캐시를 쓰므로 재실행 비용은 낮다.

각 단계는 JSON in/out이라 따로 돌리고 이어서 돌릴 수 있다. 중간에 실패해도 처음부터 다시 돌지 않는다.
`state/` 아래 파일이 단계 사이의 계약이다 — `postings.json` → `merges.json` → `gate.json`·`dropped.json`
→ `finance.json`(+`company_choices.json`) → `out/report.html`.

🔴 **캐시는 회계연도 기준으로 재검증한다.** 날짜 TTL은 공시 주기와 무관해 헛조회 또는 낡은 값을 만든다.
지금 나와 있어야 할 회계연도(한국 12월 결산 → 5월 이후면 전년도)까지 확보돼 있으면 캐시를 쓰고,
그보다 낡았거나 조회에 실패했으면 7일에 한 번 다시 본다 (`--fresh`로 전부 무시).
오늘 "DART 미등록"이던 회사가 다음 달 감사보고서를 낸다 — 실패를 영구 캐시하면 영영 못 찾는다.

### 게이트를 앞에 두는 이유

범위 밖 공고를 앞에서 잘라내면 재무 단계 대상이 절반 이하로 줄어 **공공데이터 API 호출과 실행 시간이 같은 비율로 준다.**

🔴 **지금 게이트가 쓰는 것은 지역 조건뿐이다.** `maxCommuteMin`·`maxTransfers`·`hybridFactor`·`precise`는
통근 실측 단계가 생기기 전까지 **읽지 않는다.** 적용하는 척하지 말고 콘솔·리포트에 그렇게 적는다.

### 게이트는 세 갈래다 — `drop`으로 뭉개지 말 것

| 결과 | 뜻 | 처리 |
|---|---|---|
| `pass` | 범위 안 / 풀리모트 / 관심회사 | 본 목록 |
| `hold` | 판정 불가 (근무지 비공개·"서울"처럼 광역만) | **"근무지 미확인"으로 표시하고 후속 단계도 그대로 태운다** |
| `drop` | 범위 밖 확정 | 제외. 사유를 `state/dropped.json`에 기록 |

🔴 **`중구`·`서구`·`남구`·`동구`·`북구`·`강서구`는 여러 광역시에 같은 이름이 있다.**
시·도 없이 적으면 부산 중구가 서울 중구를 찾는 사람 목록에 들어온다. 게이트가 이걸 경고한다.
행정구역 대조는 **부분 문자열이 아니라 정확 일치**로 한다 — `'서울중구'.includes('중구')`가 참이라
사용자가 `서울 중구`라고 명시했는데도 부산 중구가 통과한 적이 있다.

🔴 헤드헌터 익명 공고는 통근을 못 재도 유효한 후보다. 자동으로 버리면 좋은 자리를 잃고, **안 보이니 사용자는 그 손실을 알 방법이 없다.**

🔴 **제외 건수는 리포트에 반드시 표시한다.** 조용히 자르지 않는다.
게이트가 자른 것만이 아니라 **수집 단계의 제목 키워드 필터로 자른 것도** 같은 장부(`state/dropped.json`)에 쌓는다.
`target.roles`에 `PO`만 있고 `프로덕트 오너`가 없으면 한글 표기 공고가 전량 사라지는데,
콘솔 한 줄로 흘리면 사용자는 자기 직군 공고를 잃은 줄도 모른다.

🔴 **부분 성공을 전수로 표시하지 않는다.** 키워드별 성공·실패·잘림을 `postings.json`의 `lastRun`에 남기고
하나라도 실패·잘림이 있으면 리포트 **상단에 접지 않은 경고**를 띄운다. 조용한 부분 실패가 가장 나쁜 실패다.

🔴 **검색 조건이 바뀌면 옛 조건으로 모은 공고는 `stale`로 표시한다.** 지우지는 않는다(이력이다).
단 그 실행이 부분 실패였으면 표시하지 않는다 — 네트워크 오류를 "조건에서 빠짐"으로 오해하게 된다.

🔴 **수집이 0건이어도 파이프라인을 멈추지 않는다.** 0건은 멈출 이유가 아니라 **왜 0건인지 말할 이유**다.
`gate`는 실행 기록(`runs`)에서 사유를 꺼내 화면에 적고 빈 결과를 다음 단계로 넘겨, 리포트가 그 사유를 싣게 한다.
멈추는 경우는 하나뿐이다 — **수집 기록이 아예 없을 때**(=한 번도 안 돌렸을 때). 그때만 `collect`를 시킨다.
> 배포 후 첫 사용자 제보가 정확히 이 자리였다: 보드 접근이 막힌 사용자에게 `추천 0건`만 남았다 (개선 대장 #68).

🔴 **실패를 "조회 실패"로 뭉치지 않는다.** 차단(401·403·451)·한도 초과(429)·주소 없음(404)·서버 오류(5xx)·
네트워크 단절·타임아웃은 **대처가 서로 다르고, 그중 차단만 사용자가 고칠 수 있다**(클라우드·회사망·VPN에서 실행 중일 때).
분류와 대처 문구는 `lib/http.mjs`의 `diagnose()` 하나에서 나오고, `lib/runstatus.mjs`가 그것을
콘솔·리포트·`serve`에 **같은 문장으로** 전달한다. 화면마다 다른 말을 하면 사용자는 어느 쪽도 믿지 않는다.

## 수집 — 보드별로 방식이 다르다

`references/boards.md`에 보드별 엔드포인트·판정 신호가 있다.

| 방식 | 대상 | 규칙 |
|---|---|---|
| `api` | 공식 API가 있는 보드 (원티드 · 점핏) | 그대로 호출 |
| `web` | 공식 API가 없어 **공개 검색 페이지 HTML을 읽는** 보드 (사람인 · 인크루트) | 요청 간 1초. 로그인·유료 영역은 건드리지 않는다 |
| `saved` | **목록을 도구가 못 받는** 보드 (잡코리아 · 잡플래닛 · 로켓펀치) | 사용자가 브라우저에서 저장한 HTML 에서 **공고 주소만** 뽑고, 상세는 그 보드 파서가 읽는다 |
| `browser` | 위 셋 다 안 되는 보드 | **사용자에게 물어보고 동의하면** 브라우저로 연다 |
| `off` | 열지 않는 보드 (링크드인) | 🔴 저장본에 들어 있어도 받지 않는다 |
| `manual` | 전부 | URL·CSV 붙여넣기 |

🔴 **`api`와 `web`을 같은 이름으로 묶지 않는다.** 사람인은 공식 API가 아니라 공개 페이지 파싱이다.
둘을 뭉치면 이 도구가 무엇을 하고 있는지 문서가 흐려지고, 나중에 판단할 근거가 사라진다.
🔴 네 값(`api`·`web`·`browser`·`off`) 외의 값을 적으면 **수집이 에러로 멈춘다.**
예전에는 `off`만 봐서 `offf` 같은 오타가 조용히 수집으로 흘러갔다 — 껐다고 믿는데 계속 긁는 상태였다.

🔴 **동의 없이 브라우저를 열지 않는다.** 매번 이렇게 묻는다:

```
잡플래닛은 공개 API가 없습니다. 브라우저로 열어 수집할까요? [예 / 건너뛰기]
```

🔴 **LinkedIn은 기본 off.** 스크래핑 제재가 사용자 개인 계정에 온다.
🔴 자동 지원·이력서 자동 제출은 **만들지 않는다.** 계정 정지 위험.
🔴 요청 간 최소 1초. 백그라운드 자동 순회 금지.

### 사람인 — 원티드와 다른 세 가지 (2026-08-10 실측)

| | 원티드 | 사람인 |
|---|---|---|
| 검색 | 키워드가 정확히 걸린다 ("서비스기획" 27건) | **형태소를 쪼개 확장한다** (같은 말에 10,685건) |
| 좌표 | `geo_location` 으로 준다 | **없다** — 직선거리를 표시하지 않는다 |
| 근무지 | 한 곳 | **여러 곳일 수 있다** ("서울 강남구, 서초구, 대전 서구") |

🔴 **사람인은 "전부 훑기"가 성립하지 않는다.** 따옴표 정확검색도 무효였다(실측 동일 건수).
→ 페이지 수 상한이 아니라 **제목 매치율이 바닥나는 지점**에서 멈추고, 어디서 왜 멈췄는지 리포트에 적는다.
실측 감쇠: `p1 95% · p2 95% · p3 88% · p4 31% · p5 2% · p6 0%`

🔴 **목록의 마감 표기에는 연도가 없다** (`~ 09/20`). 여기서 연도를 추정하면 12월→1월을 넘길 때 통째로 틀린다.
마감일은 상세에서 받은 것만 쓴다.

🔴 **근무지는 목록에 첫 곳만 나온다.** 상세를 받아 전부 담고(`location.all`), 게이트는 **하나라도 들면 통과**시킨다.
시·도가 생략된 항목("서초구")은 **앞 항목의 시·도를 물려받는다** — 안 그러면 전국의 서초구가 걸린다.

🔴 **본문이 이미지뿐인 공고가 흔하다** (실측 14건 중 3건). 글자가 없는데 JD 원문 파일을 만들면
"내용이 있는 것처럼 보이는 빈 기록"이 되고 수집기가 원문 확보로 세어 다시 받지 않는다.
→ **없다고 적고 이미지 주소를 남긴다.** 조회 실패(`failed`)와 이미지형(`imageOnly`)은 다르게 다룬다 —
실패는 다음 실행에 다시 받고, 이미지형은 다시 받아도 여전히 이미지라 재조회하지 않는다.

🔴 **오픈API(`oapi.saramin.co.kr`)는 쓰지 않는다.** access-key를 요구해 "필수 키 1개" 약속이 깨진다
(commute를 착수하지 않기로 한 것과 같은 기준). 공개 검색 페이지가 키 없이 같은 정보를 준다.

## 교차 보드 중복 병합

`board:id` 유니크는 보드 **안**의 중복만 잡는다. 같은 자리가 두 보드에 동시에 올라오는 건 흔하다.

```
합칠 조건 (전부 충족)
  ① 서로 다른 보드
  ② 회사명 정규화 완전일치      🔴 부분일치 금지 ("미소" → "미소무역")
  ③ 제목 유사도 ≥ 0.8
  ④ 시·도까지 붙은 지역 키가 하나 이상 겹칠 것
```

🔴 **틀린 방향이 서로 다르다.** 안 합치면 중복 2건이 눈에 보이지만, 잘못 합치면 서로 다른 자리 하나가
목록에서 **조용히 사라진다.** → **불확실하면 합치지 않고** "중복일 수 있음"으로 표시만 한다.
지역을 모르는 쪽이 있으면 합치지 않는다. 비슷한 후보가 여럿이면 아무것도 합치지 않는다(재공고 오연결과 같은 원칙).

🔴 **제목 비교 전에 보드마다 다르게 붙이는 수식어를 뗀다.** 임계값을 낮추는 것과 다르다 —
실측에서 같은 자리가 `"서비스기획 팀원 (부산)"` vs `"서비스기획 팀원 (신입~5년 이하 / 부산)"` 로 갈려 0.64였다.
괄호 안이 **경력·지역·고용형태뿐일 때만** 뗀다. `"프로덕트 매니저 (커머스)"`와 `"(물류)"`는 여전히 다른 자리다.

대표는 **살아있는 쪽 → 좌표 있는 쪽 → JD 원문 있는 쪽 → 먼저 수집된 쪽** 순으로 고른다.
한 보드에서 내려가고 다른 보드엔 남아 있는 일이 흔해, 마감된 쪽을 대표로 세우면 산 자리가 마감으로 보인다.

🔴 **종속 레코드를 지우지 않는다.** `mergedInto` 표시만 붙이고 대표가 출처를 모은다 — 병합이 틀렸을 때 되돌릴 수 있어야 한다.
사용자가 `serve`에서 정한 것(`merges.json` 의 `decisions`)은 **규칙보다 우선**하고 다시 판정하지 않는다.

## 동명이인 — 물어보고 **기억한다**

전에는 콘솔에 후보만 찍고 미확인으로 뒀다. 그래서 같은 질문이 매 실행마다 반복됐고 사용자가 답을 알아도 반영할 수 없었다.

```bash
node scripts/resolve_company.mjs                  # 대화형
node scripts/resolve_company.mjs --list           # 후보만 보기
node scripts/resolve_company.mjs --pick "미소=2"  # 비대화형 (에이전트가 쓰는 경로)
node scripts/resolve_company.mjs --reset "미소"   # 되돌리기
```

🔴 **자동으로 고르지 않는다.** 고르는 순간 사용자가 잘못된 회사 재무를 보고 지원 결정을 내린다.
🔴 **"모르겠음"(0)도 결정으로 저장한다.** 안 그러면 같은 질문이 영원히 반복된다.
🔴 **결정과 함께 재무 캐시를 지운다.** 판정만 고치고 캐시를 두면 다음 실행이 옛 결과를 그대로 쓴다.
🔴 사용자가 고른 것도 틀릴 수 있다 → 되돌릴 수 있고, 리포트에 "확인해 붙인 재무"라고 적어 자동 판정과 구분한다.

## serve — 실제로 작업하는 화면

`out/report.html` 은 보관·공유용이라 보기 전용이다. 상태 변경·추가·숨김은 여기서만 한다.

🔴 이 서버는 이력서·자택주소·지원이력이 있는 디렉터리를 연다. 네 겹으로 막는다.

```
127.0.0.1 에만 바인딩        같은 네트워크의 다른 기기에서 열리지 않는다
매 실행 랜덤 토큰            토큰 없이는 데이터 한 줄도 주지 않는다
Host 검사                    DNS 리바인딩 차단
Origin 검사 (쓰기)           브라우저에 떠 있는 다른 사이트의 CSRF 차단
```

🔴 **브라우저를 자동으로 열지 않는다.** 주소만 찍는다 — 동의 없이 브라우저를 여는 것은 이 스킬의 금지 항목이다.
🔴 **"삭제"는 숨김이다.** 레코드와 JD 원문은 남는다. 지우면 이력이 끊겨 같은 회사에 두 번 지원한다.
🔴 편집 화면을 따로 만들지 않는다. `templates/report.html` 하나에 편집 계층만 얹는다 — UI가 두 벌이 되면 한쪽만 고쳐진다.

## 마감 판정 — 회사 단위로 되짚을 것

🔴 **공고 ID 하나만 보면 살아있는 자리를 놓친다.** 실측에서 "마감"으로 잡힌 것 중 6건이 실제로는 살아 있었다.

| 함정 | 사례 |
|---|---|
| 표의 ID가 옆 공고를 물고 있음 | 373490 vs 실제 373487 |
| 같은 자리가 **새 ID로 재공고** | 374801 → 377457 |
| 한 보드에서 내려가고 **다른 보드엔 남아 있음** | — |

→ 마감으로 판정되면 **회사 단위로 재공고를 한 번 더 검색**한다. `scripts/check_alive.mjs`가 한다.

### check_alive 의 규칙

🔴 **보드마다 판정 신호가 전혀 다르다.** 하나의 규칙으로 묶으면 한쪽이 반드시 틀린다.
그래서 `check_alive.mjs` 안에 **보드별 어댑터**로 나눠 뒀다. 새 보드는 거기만 늘리면 된다.

| 판정 | 원티드 | 사람인 |
|---|---|---|
| `alive` | `status = active` | 상태 블록이 `남은 기간` · `상시 채용` · `채용시 마감` |
| `closed` | 404 또는 `status = close` | 404 또는 `마감되었습니다` / `접수마감` |
| `unknown` | 조회 실패 | 조회 실패 **또는 상태 블록과 지원 버튼이 서로 어긋날 때** |

🔴 `unknown` 은 **마감으로 굳히지 않는다.** 다음 실행에 다시 본다.

🔴 **어느 보드에서도 날짜 경과를 마감 근거로 쓰지 않는다.** 연장·상시 전환이 흔하고,
사람인은 실측 40건 중 9건(22%)이 아예 마감일이 없는 상시·채용시 공고다.

🔴 **재검색 대조는 회사명 `includes`가 아니라 보드 회사 ID 완전일치로 한다**
(원티드 `company.id` · 사람인 `csn`). 회사명 부분일치로 채택하면 "미소 → 미소무역" 함정이 그대로 재현된다.

🔴 사람인 검색 결과에는 상태가 없다. 재공고 후보는 **상세를 받아 살아있음을 확인한 뒤에만** 목록에 넣는다.

🔴 **"같은 자리"로 자동 연결하는 것은 제목 유사도 0.8 이상이 정확히 1건일 때만.**
여럿이면 잇지 않고 "이 회사에 살아있는 공고 N건"으로만 알린다. 추측으로 잇지 않는다.
지원 이력은 연결된 새 ID로 승계하되 원 공고 키를 `history`에 남긴다.

🔴 **회사에 살아있는 공고를 전부 끌어오지 않는다.** 되찾는 것은 ① 같은 자리로 연결된 것,
또는 ② 내 직군 키워드에 걸리는 것뿐이다. 실측에서 PM 자리를 되찾으려다 같은 회사의
"Senior Backend Engineer"가 목록에 들어왔다 — **조용한 손실을 막으려다 조용한 잡음을 만드는 셈이다.**
가져오지 않은 것은 건수와 제목을 콘솔에 알린다.

## 겹침·공백 — 점수를 만들지 않고 근거만 센다

이력서와 JD 원문을 **같은 사전**(`references/jd-terms.yml`)으로 훑어 세 가지를 낸다.

```
겹침   JD 에도 이력서에도 있는 낱말          B2B SaaS · 퍼널 분석 · 0→1 출시
공백   JD 가 요구하는데 이력서에 없는 낱말    헬스케어
조건   회사가 주는 근무조건                   재택·리모트 · 스톡옵션
```

🔴 **비율·점수로 바꾸지 않는다.** `겹침 5` 는 센 것이라 눌러서 확인할 수 있지만
`fit 82` 는 확인할 방법이 없다. 「절대 하지 말 것」 1번이 이것이다.

🔴 **판정은 세 갈래다. `겹침 0` 으로 뭉개지 말 것.**

```
ok       대조했다
thin     본문은 읽었으나 사전에 걸린 낱말이 없다  → 사전이 그 직군을 못 따라간 것이다
unknown  본문을 못 읽었다 (이미지뿐 · 비어 있음 · 120자 미만)
```

못 읽은 것과 안 맞는 것을 같은 칸에 넣으면 본문이 이미지뿐인 공고가 전부 최하위로 밀려
목록에서 조용히 사라진다. 사람인·인크루트에 그런 공고가 흔하다. 정렬도 `unknown` 을
맨 아래로 보내지 않는다.

🔴 **이력서와 JD 를 같은 함수로 훑는다**(`termsFromText`). 한쪽만 다른 규칙으로 뽑으면
겹침이 규칙 차이 때문에 생기거나 사라진다. 그건 근거가 아니라 잡음이다.

🔴 **근무조건은 겹침·공백에서 뺀다.** 재택·스톡옵션은 이력서에 적을 것이 아니라 회사가 주는 것이다.
"재택 공백" 은 사실이 아니라 오해다.

🔴 **`fit.terms` 를 자동으로 채우지 않는다.** `fit.mjs --terms` 는 출력만 하고 멈춘다.
확인 없이 넣으면 사용자가 본 적 없는 낱말로 목록이 정렬된다.

🔴 **`report.html` 에는 기본으로 싣지 않는다.** 겹친 낱말은 이력서에 무엇이 적혀 있는지를
그대로 드러낸다 — 그 파일은 남에게 보낼 수 있다(「절대 하지 말 것」 6번).
넣으려면 `render.mjs --with-fit` 을 명시해야 한다. 손에 들고 보는 화면은 `serve` 가 맡는다.

**사전이 곧 시야의 한계다.** 없는 낱말은 겹침으로도 공백으로도 안 나온다.
직군을 늘리려면 `references/jd-terms.yml` 에 줄을 더한다.

## 재무 — 폴백 체인

```
① 공공데이터포털 기업개요  → 법인등록번호(crno) + 등기주소 + 종업원수
② 공공데이터포털 기업재무  → 매출·영업이익·자본총계
   ↓ 없으면
③ DART 공시 (키 불필요)    → 정기보고서 우선, 없으면 감사보고서 원문 파싱
   ↓ 없으면
u 미확인 + 면접 질문 생성
```

실측 확보율은 **표본에 따라 크게 갈린다.** 근거 없이 한 숫자로 뭉뚱그리지 않는다.

| 표본 | 확보율 | 성격 |
|---|---|---|
| 구직 후보 98곳 (2026-08-10, M0) | **62.2%** | 대기업·유명 스타트업이 섞인 목록 |
| 원티드 수집 30곳 (2026-08-10, M2) | **50.0%** | 실제 파이프라인 출력. 소규모·초기 회사 비중이 높다 |

30곳 중 미확인 15곳의 내역: DART 미등록 8 · 동명이인이라 미채택 4 · 2023년 이후 공시 없음 3.
**절반은 "데이터가 없어서"가 아니라 "붙이면 안 돼서" 미확인이다.** 이 구분을 리포트에 그대로 적는다.

### 🔴 회사명 매칭 — 부분일치는 절대 채택하지 않는다

```
완전일치 1건   → 채택
완전일치 2건+  → 등기주소로 구분, 하나로 안 좁혀지면 ambiguous (사람에게 물어본다)
부분일치만     → 실패 처리
```

부분일치를 구제하려다 **서로 다른 회사가 같은 법인에 붙는 사고가 5건** 났다.
매칭 실패는 불편할 뿐이지만, **오매칭은 사용자가 잘못된 회사 재무를 보고 지원 결정을 내리게 한다.**

🔴 **대조 기준은 "검색에 쓴 이름"이지 공고에 적힌 원본이 아니다.**
`럭스로보(LUXROBO)`로 검색해 등기 상호 `럭스로보`를 받아 놓고 원본과 비교하면 완전일치가 안 나
**공시가 18건 있는 회사가 "DART 미등록"으로 떨어진다.** 가드가 지나쳐도 제품은 죽는다.

🔴 **`(주)`·`㈜`는 이름의 일부가 아니다.** 괄호 안을 별칭으로 뽑는 코드가 `(주)골프존`에서 `주`를 꺼내
`주 주식회사`로 조회했고, 그 결과 골프존과 델레오코리아에 **같은 법인번호**가 붙었다.

DART 경로에서도 같다 — 이름만으로 채택하지 말고 **법인등록번호를 대조**한다. 기업개황 팝업에 들어 있다.

### 🔴 감사보고서 파싱에서 값을 치른 함정 3개

`scripts/lib/dart_table.mjs`에 방어 로직이 들어 있다. 직접 파싱을 새로 짜지 말고 이 모듈을 쓸 것.

| 증상 | 원인 |
|---|---|
| 전 건 "파싱 실패" | 뷰어 HTML 구조 오판. **데이터 부재와 파서 버그를 구분하라** |
| 쿠팡 매출 23억(실제 41.9조) | 텍스트 정규식이 **주석 컬럼("23,28")을 값으로** 집음 → 표 구조로 읽어야 한다 |
| 적자 회사가 **흑자로 뒤집힘** | 한국 손익계산서는 적자면 계정명이 **"영업손실"이 되고 값은 양수**. **부호가 라벨에 실린다** |

### 등급 룰

| 등급 | 조건 |
|---|---|
| `r` 위험 | 자본총계 ≤ 0 (완전자본잠식) 이고 영업흑자도 아님 |
| `w` 경고 | 자본잠식이나 영업흑자 / 영업적자 2년 이상 / 부채비율 > 400% / **적자인데 자본 완충이 3배 미만** |
| `g` 좋음 | 영업흑자 2년 연속 이고 자본총계 > 0 이고 매출 성장 |
| `o` 양호 | 흑자이나 좋음 조건 미달, 또는 적자지만 자본총계가 연간 영업적자의 3배 이상 |
| `u` 미확인 | **데이터가 없을 때만** |

위에서부터 먼저 맞는 것 하나만 적용한다. 자본총계 ≤ 0이면 부채비율을 계산하지 않는다(분모 붕괴).

🔴 **`u`는 "데이터 없음"이지 "판정 못 함"이 아니다.** 숫자가 있는데 `u`가 뜨면 사용자는 공시가 없다고 읽는다.
   실측에서 "적자 + 자본 완충 1~3배"가 어느 분기에도 안 걸려 `u`로 떨어졌다. 그 구간은 `w`다.
🔴 **등급에 기준연도를 반드시 병기한다.** 최신 자료가 3년 이상 낡으면 `u`로 내린다.
🔴 자본총계가 연간 영업적자의 **10배 이상**이면 강등하지 않는다 (대규모 조달 기업 오탐 방지).
🔴 **공공데이터포털에서 낡은 연도만 나왔으면 거기서 멈추지 말고 DART를 마저 본다.**
   2023년치만 받고 확보로 치면, DART에 올라온 올해 감사보고서를 통째로 놓친다.

### 투자 정보 — 재무제표가 못 보는 것

재무제표는 **작년 이야기**다. 자본잠식으로 찍힌 회사가 올해 유상증자를 받았으면 상황이 다르다.
그래서 DART 공시 목록에서 **조달 사건**을 함께 뽑는다 (`lib/investment.mjs`).

| 세는 것 | 안 세는 것 |
|---|---|
| 유상증자 결정 · 증권신고서(지분증권) · 소액공모 → **지분 조달** | **무상증자** — 잉여금을 자본금으로 옮기는 회계 처리다. 돈이 안 들어온다 |
| 전환사채 · 신주인수권부사채 · 교환사채 발행 결정 → **부채 조달** | **자기주식 취득 · 주식 소각 · 유상감자** — 돈이 **나간다** |
| | **타법인 주식 취득** — 회사가 **남에게** 투자한 것이다 |
| | **대량보유상황보고** — 기존 주주끼리의 매매다. 회사로 들어온 돈이 아니다 |

🔴 이 구분이 이 기능의 전부다. 무상증자를 투자로 세면 회계 처리가 자금 유입으로 둔갑하고,
   자기주식 취득을 세면 **돈이 나간 회사가 돈을 받은 회사로 보인다.**

**등급을 움직이는 경우는 하나뿐이다.**

| 조건 | 결과 |
|---|---|
| `r` 위험 + 최근 **12개월** 안의 **지분** 조달 | `w` 경고 — **한 단계만** |
| 그 외 전부 | 등급 그대로. 조달 사실만 근거에 싣는다 |

🔴 **금액은 모른다.** 공시 제목만 보기 때문이다(원문을 열면 회사당 요청이 한 번 더 늘고,
   서식이 제각각이라 금액 오추출이 곧바로 잘못된 등급이 된다). 그래서
   ① 올리는 폭을 한 단계로 묶고 ② **"금액은 공시 원문에서 확인해 주십시오"를 문구에서 빼지 않고**
   ③ 리포트에 **공시 원문 링크**를 붙인다 — 링크가 곧 근거다.
🔴 **전환사채는 위험을 내리지 못한다.** 부채로 들어온 돈이라 자본잠식 판정을 뒤집을 근거가 아니다.
🔴 등급이 조달 때문에 움직였으면 **움직이기 전 등급(`gradeBeforeInvestment`)을 함께 남긴다.**
   근거 없이 바뀐 것처럼 보이면 안 된다.
🔴 공공데이터포털만으로 재무가 끝난 회사도 **조달 공시를 보려면 DART를 봐야 한다.**
   그 회사만 DART 조회가 새로 붙는다 — **최소 2건**(공시검색 + 기업개황)이고, 이름 변형이나
   동명이인 후보가 있으면 `resolveDartCorp()` 가 변형별로 검색하고 후보별 개황을 보므로 **더 늘어난다.**
   끄려면 `profile.yml` 의 `finance.investment: false`.
🔴 **투자 정보를 켜면 캐시 재검증 주기가 달라진다.** 조달 공시는 회계연도와 주기가 다르다 —
   다음 달 유상증자가 올라와도 회계연도는 그대로다. 재무만 보고 신선하다고 하면 새 조달이 영영 안 붙고
   위험 등급이 그대로 굳는다. 그래서 최신 재무가 있어도 **7일마다 다시 본다** (`lib/freshness.mjs`).
   기능이 생기기 전에 만들어진 캐시(= `investment` 필드가 없는 것)는 즉시 무효로 본다.

**커버리지는 회사에 따라 크게 갈린다.** 조달 공시는 사업보고서 제출 대상(상장 + 대형 비상장)만 낸다 —
실측(2026-08-18): 비바리퍼블리카 8건 · 웹케시 0건 · 당근마켓 0건.
**없는 것을 "투자 없음"으로 적지 않는다.** 공시가 없으면 아무 말도 하지 않는다.

### 기준선 대비 ▲▼

프로필에 현직장이 있으면 그 회사 재무를 자동 조회해 기준선으로 잡는다.
매출·영업이익·자본총계 **3개 중 2개 이상**이 나으면 ▲, 못하면 ▼. 기준선이 없으면 배지 자체를 만들지 않는다.

`templates/report.html` + `data.json` → `scripts/render.mjs`가 만든다. **외부 리소스 0, 인라인 CSS/JS만.**

- 통근 배지는 지역 칸 아래 2행째. 근사치는 앞에 `≈`를 붙이고, **회사 간 비교에 쓰지 말라고 툴팁에 적는다**
- 진행상태는 `state/applications.json`에 저장한다 (브라우저 localStorage 아님 — 기기가 바뀌면 사라진다)
- 하단에 제외 건수와 사유를 펼침으로 넣는다

🔴 **지원 이력(면접·탈락)은 리포트에 기본으로 넣지 않는다.** `--with-status`로 명시해야 들어간다.
report.html은 공유용이라고 문서에 적어 두고 지원 상태를 실어 보내면, 파일 하나로 그 약속이 깨진다.
실수로 새는 쪽이 실수로 빠지는 쪽보다 훨씬 비싸다.

🔴 리포트의 "살아있음"은 **alive 를 마지막으로 돌린 시점 기준**이다. 그렇게 적는다.

🔴 **같은 자리가 두 보드에 있으면 출처 링크를 둘 다 싣는다.** 한쪽이 먼저 내려가기 때문이다.

🔴 **켜 놓고 한 번도 안 돌린 보드가 있으면 리포트 상단에 경고를 띄운다.** 그 보드에만 올라온 공고는
사용자에게 존재 자체가 안 보인다 — 조용한 손실 중 가장 큰 것이다.

## 절대 하지 말 것

1. **궁합 점수·합격률처럼 보이는 숫자를 만들지 않는다.** 검증할 수 없다.
   겹침·공백은 **센 낱말**이라 괜찮다 — 그것을 비율 하나로 뭉치는 순간 선을 넘는다
2. **추측한 값으로 공고를 버리지 않는다.** 확실하지 않으면 `hold`
3. **자동 지원·이력서 자동 제출을 만들지 않는다**
4. **동의 없이 브라우저로 크롤링하지 않는다**
5. **API 키 값을 stdout·로그·에러 메시지에 출력하지 않는다.** URL 로깅 시 `serviceKey`를 마스킹한다
6. **자택 주소·이력서 내용을 리포트에 출력하지 않는다**
7. **부분일치로 회사 재무를 붙이지 않는다**
8. 근거 없는 커버리지·정확도 숫자를 말하지 않는다
